# コントローラ入力の方向確認

Escの「コントローラ」からP1/P2を選び、QRまたは実機のガード＋リセット1秒同時押しで登録する。実機は登録後Escへ戻る。スマホは接続後、軸順序6通り（XYZ/XZY/YXZ/YZX/ZXY/ZYX）と出力X/Y/Zそれぞれの正転・反転を選ぶ。右側の剣先表示で実際の動きを確認し、「完了」で保存応答を受けてEscへ戻る。

`ControllerRegistrationPanel` がこの導線を担当する。軸はスマホのローカル座標系へ適用し、設定確定時には次の新しい姿勢から正面基準を作り直す。設定前の遅延パケットはnextSequenceで除外し、設定変更そのものを攻撃やメニュー移動にしない。元の `ControllerAxisCalibrationPanel` は内部の方向診断APIとして維持するが、Escには独立した入口を表示しない。

メニュー操作と方向表示は、ゲームと同じリセンター基準から得た剣の姿勢を使う。連続する姿勢サンプルから剣先の移動方向と速度を求め、360°/秒を超えた方向を表示・入力する。剣の軸まわりのひねりは剣先を動かさないため、方向入力にならない。ジャイロの軸や入力源ごとの符号を使った補正は行わない。

同じパケットを複数の描画フレームで読んでも入力を繰り返さない。姿勢失効、入力源の変更、リセンター、時間の逆行や大きなサンプル間隔で過去の移動を再生しない。メニュー操作、方向表示、戦闘は同じ正規化済み剣姿勢を参照する。

`MotionController.TryGetMenuSample` は最新サンプルからゲームと同じ `baseRotation * inverse(referenceRotation) * sampleRotation` を計算する。`SwordMotionDirection` は2つの剣姿勢から剣先の移動を求め、メニュー操作と方向表示で共有する。`ControllerAxisCalibrationPanel` は接続確認、リセンター、方向表示を提供する診断画面である。

2026-10-16: メニューの画面座標への変換は `SwordMotionDirection` で `(tipVelocity.x, -tipVelocity.z)` とする。方向表示も同じ投影を使い、上下左右の反転修正を戦闘の正面合わせ・剣姿勢へ持ち込まない。

2026-10-16再指定: メニューは剣先の投影を廃止し、角速度ベースへ戻した。実機は基板補正後のローカル角速度、スマホは従来の固定ワールド変換を使う。右は+Y、上は−X。`TryGetMenuSample`は正面合わせ前の生サンプルを返し、メニュー操作と方向表示は`MenuAngularMotion`を共有する。リセット位置で操作の軸が変わらない。ジャイロが使えない場合は姿勢の角度差と機器時刻から補う。
