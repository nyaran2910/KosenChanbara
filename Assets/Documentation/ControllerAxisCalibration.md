# Unityでの軸合わせ

開始前のタイトル・選択画面でEsc →「軸合わせ」→ P1/P2を選ぶ。現在使っているスマホまたはコントローラが対象になる。スマホ優先の接続ルールは維持する。

6つの項目を選ぶと、その場でメニューの軸を変更する。ゲーム中の剣の姿勢・角速度・突きの加速度は変更しない。上部の「振った方向」を見ながら上下左右に振り、合う項目を選んだまま戻れば設定完了。記録、カウントダウン、自動推定、追加の適用ボタンは使わない。

| 項目 | 補正後のX / Y / Zへ使う軸 |
|---|---|
| 1（標準） | X / Y / Z |
| 2 | X / Z / −Y |
| 3 | Y / X / −Z |
| 4 | Y / Z / X |
| 5 | Z / X / Y |
| 6 | Z / Y / −X |

軸の並び替えは3! = 6通り。符号反転をすべて独立に選ぶ設定ではない。メニュー用サンプルを同じ回転基底に揃えるため、奇数置換では3番目の軸の符号を補正する。項目1は元のスマホ・コントローラの入力処理をそのまま使う。スマホメニューの固定ワールド基準も復元する。

選択した項目はチェックと青い背景で示す。振ると上部の方向表示を更新し、その方向へカーソルも1項目移動する。カーソル移動だけでは軸を変えず、ガードで選んだ項目を適用する。プリセット画面では選んだP1/P2の入力だけを使う。マウス、矢印キーとEnter、ガードで項目を選べる。短いリセットは通常の正面合わせ。プリセットの変更時には新しい正面姿勢を取り直さない。Escと「もどる」は選択した設定を保ってEsc画面に戻る。

方向表示はメニューと同じ360°/秒を超えた方向を使い、最後に検出した方向を保持する。連続した速い動きでも方向の変化を表示する。姿勢のみの入力は端末時刻から角速度を求め、同じパケットの再読込み、時計リセット、通信間隔が大きい場合に偽の方向を表示しない。

設定はこのUnity実行中のP1/P2・入力源別に保持する。正面合わせや画面遷移では消さない。新しいスマホ接続には前の端末の設定を引き継がない。アプリ終了後の保存は行わない。

`ControllerAxisCalibrationPanel` が独立した入口と画面を持ち、`ControllerAxisMapping` が6通りの補正、`AxisDirectionMonitor` が方向表示を担当する。既存の基本操作3ボタンのCanvas、シーン、送信側、パケット形式、受信時の座標変換は変更しない。入口はゲーム中・プレビュー中には表示しない。

`ControllerAxisMappingTests` と `ControllerAxisCalibrationPlayTests` は6通りの軸の一貫性、連続入力と端末時刻、P1/P2×スマホ/コントローラの即時切替・方向表示・選択保持、他の入力への非干渉、標準への復元、接続変更を検証する。

## メニューの補正を戦闘へ適用しない

スマホによっては姿勢のquaternionは正常でも、メニューに使うrotationRateの軸が異なる。この場合、メニューに合うプリセットを剣の姿勢にも適用すると正常なゲーム操作がずれる。6プリセットはメニュー専用の設定とする。スマホとコントローラのどちらでも、戦闘は元のセンサーデータと通常のリセンター基準を使う。

`SetMenuAxisMapping` はプリセットの保存と `MenuPoseGeneration` の更新だけを行う。正面合わせや姿勢の無効化、戦闘の入力世代・突き履歴の初期化は行わない。通常の正面合わせ・入力源変更・姿勢無効化は従来通り `PoseGeneration` を更新し、メニューの世代も更新する。メニューのカーソル入力は `MenuPoseGeneration` を使い、切替時の座標の飛びを移動として扱わない。

検証では「上振りのquaternionは正しいが、rotationRateは左扱いになる」入力を用意する。メニュー補正で左表示が上表示へ直る一方、剣の姿勢・角速度・リセンター基準が完全に保持されることを確認する。P1/P2、スマホ/コントローラ、6プリセット、複数のリセンター姿勢でも戦闘入力と突きが変わらないことを検証する。
