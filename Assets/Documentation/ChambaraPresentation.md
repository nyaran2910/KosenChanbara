# チャンバラの参照資料と実装仕様

調査日: 2026-10-03〜04。対象は **Wii Sports Resort の Swordplay / チャンバラ**。以下はプレイの流れ・判定・視覚的な読みやすさを参考にした独自実装で、原作の映像、モデル、音声、音楽を取り込んだものではない。

- [任天堂「社長が訊く Wii Sports Resort」70 人を相手にする仕組み](https://www.nintendo.com/en-gb/Iwata-Asks/Iwata-Asks-Wii-Sports-Resort/Wii-Sports-Resort/3-Magic-That-Lets-You-Take-On-70-Opponents/3-Magic-That-Lets-You-Take-On-70-Opponents-220282.html): 大勢と戦う体験と操作の直接性についての開発者説明。**100 人が原作共通の人数だとは扱わない**。

判定の詳細を照合した二次資料:

- [GameFAQs: Wii Sports Resort FAQ](https://gamefaqs.gamespot.com/wii/950923-wii-sports-resort/faqs/60640): 剣の向きに応じた攻撃・防御、Showdown の敵の耐久差。
- [日本語攻略 Wiki: チャンバラ・組み手](https://w.atwiki.jp/wiisportsresort/pages/25.html): 対象となる敵が攻撃し、周囲の敵は待機する戦闘構成。
- [Showdown の概要](https://wiisportsresort.fandom.com/wiki/Showdown): 体力 3、敵の耐久 1〜3、敵数と進行の説明の補助確認。

秒単位のカメラやアニメーションを原作映像から計測したものではない。以下の時間・効果量は本作の入力遅延と既存ゲーム判定に合わせて設定している。

## 今回のルール

ユーザー指定を優先し、Duel は **3 本先取**、Single は **100 人でクリア**へ変更する。引き分けは両者に1本ずつ加点する。同点で3本へ到達した場合は「最終決戦」を表示し、時間無制限で点差がつくまで続行する。最終決戦の同時場外でも両者に加点して続行し、再戦では通常の60秒制限へ戻す。原作そのままのルールという説明はしない。

`Combat/MatchProgress.cs` がシリーズと Showdown の有限進行を管理する。時間源はポーズで止まる gameplay clock。

キャラ選択の「プレビュー」は選択済みの本人と剣を、実フィールドで正面から1体だけ表示する。`MasterController.Preview` は試合と共通の `ReadInput` → `SwordPoseMath` → `DuelAvatar` を使い、スマホ・リモコン・キーボードの姿勢とガード、突きの手元伸縮を反映する。Singleの本人は両入力slotを受ける。戦闘判定、出現、得点、試合時計は進めず、プレビューの演出には別のunscaled時計を使う。既存の入力rootは停止しない。戻る時はカメラ・隠したrendererを復元し、キャラ選択の確定状態と移動中のカーソルを保持する。Escの接続ポーズも使える。

| 場面 | 実装 |
| --- | --- |
| 対戦前 | 3.2 秒の VS、両者の剣を操作可能。ダメージ判定は開始しない |
| ラウンド開始 | 「N本目」を 1.3 秒、「かまえて！」を 1.2 秒、開始後に短い「はじめ！」表示 |
| 対戦 | 60 秒。タイムアップは引き分けで両者に1本ずつ加点 |
| 落下 | 「場外！」、負け側の転落、遅れて水しぶきと効果音、得点更新 |
| 次のラウンド | 3.4 秒の結果表示後に配置と剣の履歴をリセット。シリーズ得点は保持 |
| 決着 | 3 本以上かつ点差がついたら勝者を表示。「もう一度あそぶ」「モードを選ぶ」「キャラクターを選ぶ」へ進める。再戦では得点・時間・演出を初期化 |
| Single | 開始表示、倒した人数 / 100、3 つのハート、クリア / 敗北と同じ3つの結果操作 |

Singleはイージー／ノーマルをメニューで選ぶ。ノーマルの進行値は従来どおり、イージーは出現間隔と攻撃準備を1.5倍、斬りの時間を1.35倍にする。Single は通常敵 1 耐久、10 体ごとに 2、25 体ごとに 3 の耐久を持たせ、生き残った敵は被弾ごとに縦・横のガードを切り替える。3体に1体は初回だけ3.4mから攻撃を準備しながら近寄り、通常敵は2.35m以内で準備する。他の敵に遮られず、間隔を確保できた敵は並行して攻撃する。頭上は残り耐久だけを表示し、攻撃ゲージは使わない。実際に振り出す直前の0.18秒だけ剣元が光る。同時出現数は区間1〜3で2体、4〜7で3体、8〜10で4体までに制限する。区間が進むほど接近・攻撃を速め、出現間隔は1.85秒から0.95秒へ短縮する。撃破後には最低0.65秒の間を空ける。プレイヤーの攻撃は有効な振りの間、実際の刃の移動を連続して検査し、1回の振りで命中する敵は1体に限る。防御切り替えや自動旋回は攻撃の軌道に含めない。敵の剣は防御・予備動作・攻撃・復帰を連続補間する。視点は加速と減速を使って対象へ向く。プレイヤーは被弾後1.5秒の無敵時間を持ち、同時接触でハートが一度に失われない。100体の撃破後には新規敵を出さない。

剣の表示モデルだけでは判定は決まらない。Duel／Single／Freeは攻撃受付を `AttackStroke`、有限長の接触と守り解決を `CombatContact`、ガード角を `CombatGuard.CanBlock` で共有する。手元から0.55〜2.1mの有効刃を連続補間して、キャラの胸位置と姿勢補正に追従する3つの体球（半径0.43m）への接触を検査する。Duelも角度だけでは命中せず、剣が届かない距離では攻撃が当たらない。同時攻撃は両方の刃を同じ時刻で補間し、胴体接触より先に交差したら相殺する。

斬りは80°以上の構えから40°/s以上で45°以内へ振り込むと開始する。開始後0.7秒以内の前向き軌道なら減速しても継続するが、刃の回転が0.05°未満のフレームは接触を受け付けない。呼吸による手元だけの移動、戻し、無効姿勢、ガード、入力世代変更で命中を作らない。斬りのガードは交差角が60°を超えること、有効な姿勢で正面から受けること、実際の守り刃との交差を要求する。守り接触の許容幅は両モード共通で0.20m。胴体境界の厚みで先に接触した場合も、同じ斬りの残りの軌道が実刃と交差すれば守り成功とする。遠く離れた刃・背後からの攻撃は防げない。Duelのガード成功押し戻しは2.0m、Singleの敵押し戻しは0.20mとして従来より20%減らし、反撃時間は維持する。

突きはセンサー入力のみ。前向き25°以内の剣と、前方3m/s²以上・35ms以上・積分推進量0.16m/s以上の新鮮な加速度で1回受付し、静止100msで再準備する。再受付間隔は450ms、スマホ／リモコンとも加速度の鮮度は100ms以内。手元を最大0.35mだけ0.06秒で伸ばし、0.20秒までに戻す。攻撃窓は最大0.30秒だが、接触受付は手元が前進しているフレームだけで、引き戻しでは命中しない。正面の胸前に実際の守り刃がある場合、縦・横・斜めの全方向のガードで突きを防ぐ。非ガードの突きは斬りの1.2倍押し戻す（Duelは3.6m、Singleは0.48m）。Singleは両コントローラの突きを消費し、発動側の姿勢を伸縮中だけ保持する。演出・ポーズ中の要求は破棄する。敵は斬りだけを行う。

`ShowdownCourse` は10人ずつ全10区間を管理する。各区間の全撃破後、プレイヤーは次の地点へ1.4 m/sで自動歩行し、移動中は敵の出現・接近・攻撃を停止する。到着後は0.75秒空けて次の区間を開始する。区間と移動進捗をHUDに表示する。既存の円形平台内に配置した独自コースで、原作の島や地形の再現ではない。移動経路は平台の内側半分、敵は半径の88%以内に制約し、ポーズ中は歩行と時計を停止する。リトライで区間・敵・体力を初期化する。

## 見た目と操作感

- VS 中は各プレイヤーの正面寄りにカメラを置き、ラウンド開始へ向けて通常視点へ戻す。
- 接触は色付きの火花と短い白い中心光、画面フラッシュ、カメラ反応、合成効果音を組み合わせる。
- 落下では骨格モデルを傾けて下降させ、水しぶきのタイミングを遅らせる。
- プレイヤーの剣姿勢は前口上中にも更新する。ゲーム判定だけを Fight phase に限定する。
- 手元にはキャラクターの防具と同じ色の球を2つ、両手としてを表示する。
- 組み手の撃破では実メッシュの最低点を床へ合わせ、0.48秒で倒れた後、0.82〜1.15秒にかけて小さくなって退場する。場外の転落とは別の処理にする。
- 通常姿勢で刃先を後ろへ向けたときは、上・後方への入力を楕円状の範囲で評価し、上向き成分があるときだけ握りを滑らかに頭上へ持ち上げる。水平の側面・背面旋回では持ち上げず、手元を胸の周りから体の後ろへ回し、刃を外向きに保つ。刃の入力方向を保ちながら胴体を横断する姿勢を避ける。防御中は正面の防御面を保ち、刃が胸の前を横切る投影位置を保ち、上下角度に応じて防御面の中心を最大18cmだけ変える。防御で剣の素材色は変えず、接触の火花だけを表示する。
- ポーズ中は試合時間、ラウンド時間、演出時間を進めない。再開時は速度履歴を捨てて突然の攻撃を防ぐ。

HUDと結果画面は背景板なしで、必要な得点・体力・決着表示・押すボタンを残す。日本語フォントはOSにあるヒラギノ・游ゴシック・メイリオ・Noto Sansなどから選ぶ。2026-10-05のユーザー指定により操作説明はすべて表示せず、入力機能は維持する。メニューは端末の絶対姿勢で角速度を固定のメニュー座標系へ変換し、振った方向が360°/秒を超えると1項目移動する。360°/秒以下になれば次の入力を受け付け、戻す動作の専用抑制は設けない。結果画面では両方のコントローラーが同じ選択位置を動かし、防御ボタンで決定する。リセット短押しは結果画面を含む全画面で正面合わせを行い、キャラクター選択へは結果ボタンで戻る。`DuelPresentation.ResultVisible`、`ResultSelection`、`NavigateResult(Vector2Int)`、`ConfirmResult()`をメニュー制御と共有し、結果の再表示や再戦では先頭の選択に戻す。

`DuelAvatar` の脚は imported FBX の上腿・下腿・足首に対する 2-bone IK。接地位置と接地中の足首回転を **world 座標**で保存する。前傾、旋回、親オブジェクトの押し戻しで支持足を滑らせず、左右交互の遊脚で新しい足場へ移る。脚長から支持足へ届く骨盤位置を求め、膝が逆向きに折れることを防ぐ。剣を横へ倒しただけでは前方への踏み出しを起こさない。

既存のゲーム判定は 3 m / 0.12 秒の押し戻しなので、その速度のまま歩行アニメーションを付けると足が滑る。判定位置を変えず、視覚モデルが最大 6 m/s で追従し、短い回復歩行で姿勢を取り戻す。リトライやラウンドリセットでは接地点も新しい開始位置へ再初期化する。

回復歩行の歩幅は両脚が届く範囲へ制限し、支持脚と遊脚の両方から骨盤位置を補正する。遊脚は高さ7cmの弧に沿って移動し、押し戻し中に脚が伸び切って足首が不自然に跳ね上がることを防ぐ。実際の押し戻しを使うテストで、30/60/144 FPSの接地、足首の軌道、左右の踏み替えと停止後の収束を確認する。

## 回帰確認

- `MatchProgressTests`: 3 本決着、引き分けの両者加点、同時3本到達時の最終決戦と時間無制限・再戦での解除、一方だけが3本に到達する場合、二重加点防止、時間切れ、停止時計、100 人で終了、3 被弾、無敵時間、リトライ。
- `SwordPoseTests`: 後方へ向けた剣の頭上位置と連続性、防御時の上下角度による高さ変化、既存の剣姿勢・防御投影・左右反転。
- `DuelPresentationResultPlayTests`: 対戦・組み手双方で結果の3操作、共通の選択位置、引き分け表示、再戦時の初期化、モード選択・キャラクター選択への復帰。
- `BattleGroundPlayTests`: 実際の接触から得点・シリーズ結果・再戦、既存の姿勢・ガード・カメラ・踏み込み。
- `CombatContactTests`: 同じ有限刃での両モード接触、実際の8方向ガードで突き防御、到達しない攻撃・遠いガード・静止刃・呼吸による手元移動・突きの引き戻しの除外、同時刻での剣交差、減速した斬りと無効入力。
- `ThrustGestureTests` / `MotionSourceSwitchPlayTests`: 突きの前向き・加速度・継続時間・一度だけの消費・再準備・古い入力の除外。スマホ／リモコン両経路の入力テストは6件を確認済み。リモコンの加速度送信はP1/P2ともビルド済み、P1はUSB書き込み・hash検証済み。書き込み後の実加速度とP2実機は未確認。
- `AvatarGroundingPlayTests`: 実 FBX の P1/P2、30/60/144 FPS、前後左右の押し戻しと旋回、world 支持足、膝の曲がり、床への侵入、左右同時ステップ防止、収束とリセット、横姿勢での誤踏み出し防止、全キャラクターの撃破時の床接触と縮小のリセット、全色の両手の球、実メッシュの頭上を通る剣。
- `ShowdownCourseTests` / `ShowdownCoursePlayTests`: 10人ごとの出現制限、全10区間と100人での終了、30/60/144 FPSの歩行、平台内の経路、移動中の停止、ポーズ・タイトル復帰・リトライ。

これらの自動テストは動作・幾何の回帰確認であり、原作との映像上の完全一致や ESP 実機の応答を保証するものではない。
